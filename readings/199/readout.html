由 pnpm bench:coverage 逐条解析并拒绝四类漂移：声称有数却解析不出、absent 的理由短到不能当计划、把 1,418 张图写成「1,418 percent」、被点名的榜从清单里消失。读数：4 measured / 1 partial / 4 absent。

三个 absent 的原因互不相同：nvBench 2.0 是方法缺口（一题出一张图的产品，不能在「要一组」的指标上被打分），VisCodeBench 是契约缺口（要写 Python 进 notebook），Spider 是判定器缺口（只有执行判定，缺官方 EM）。这三种缺口要花的力气差一个量级，台账把它们分开写就是为了不让它们混成一句「还没做」。

判据在派发前写死为 ≥405/600（零调用族上界 401 与 recall@3 口径 409 的中点）。配对精确 McNemar：单源↔规则 42:43（p=1.0000）、单源↔选择器 37:39（p=0.9088）、规则↔选择器 34:35（p=1.0000）。三臂在准确率上互相不可分辨，唯一可分辨的是账单。

最硬的一条证据在账单里：选择器那次调用是 427 prompt token（374 未命中）+ 1 个 completion token。它做的是位置判断，而位置判断零调用的规则免费在做，且做得略好（388 对 387）。

三条断言同时关闭：零调用族（上界 401，因为 485/600 = 80.8% 的题所有候选同形）、付费选择器（相对规则 −1 题）、池本身（单源 389 对三候选池 388，调用 3 倍）。

8pp 余量在选择器之外：recall@3 72.7% 对准确率 64.7%，那 48 题的特征是三个 prompt 写了同一句错话——知识缺口，不是判别缺口。所以下一个候选源必须差在知识上（行样本 / 值检索 / 外部证据），判据先登记 ≥406 且独占胜出 ≥11 题。
